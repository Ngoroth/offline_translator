## Challenges & Issues Discovered

### Critical Bug Fixed During Retrospective

**VAD Multi-Segment Bug (FR11 Violation)**

- **Problem:** After the first silence detection, subsequent speech segments were not being harvested and sent to STT
- **Root Cause:** `session.state` was set to `PROCESSING` in STT worker and VAD worker was skipping chunks when `state != LISTENING`
- **Impact:** Broke FR11 (Users can speak up to 10 phrases in one hold session using auto-segmentation)
- **Resolution:** Removed state check in VAD worker, allowing continuous segment harvesting regardless of processing state
- **Files Changed:** `src/app/orchestrator/pipeline.py`
- **Test Added:** `test_vad_multiple_segments_harvested` in `tests/integration/test_pipeline_vad.py`

## Vision & Future Ideas

### Android Port (User Suggestion)

Ngoroth suggested exploring Android as a platform instead of/alongside Raspberry Pi:

- **Rationale:** Modern Android phones are more powerful than RPi 5, have built-in microphone, speaker, and screen
- **Benefits:** Simplified hardware setup, better availability, touchscreen UI
- **Challenges:** Architecture requires Python 3.12, asyncio, and native libraries (faster-whisper, llama-cpp, piper-tts)
- **Potential Approaches:**
  1. Termux/Pydroid (limited)
  2. Kotlin/Java native rewrite
  3. React Native / Flutter with native AI bindings
  4. ONNX Runtime Mobile

This aligns with PRD Phase 3: "Mobile versions (Android/iOS)". Requires research spike before planning.
