Modify `src/app/utils/vad.py` to replace the bare `pass` in the exception handler with proper error logging:

1. Add import at top of file: `from loguru import logger`
2. Replace lines 44-49 (the exception handler):
   ```python
   # Current (BAD):
   except Exception:
       pass

   # Replace with:
   except Exception as e:
       logger.error(f"VAD is_speech error: {e}")
   ```

**Do NOT change** the control flow - the method should still return `has_speech` even on error, just with logging.

  <name>Add session context to pipeline error logs</name>
  <files>src/app/orchestrator/pipeline.py</files>
  <action>
Modify `src/app/orchestrator/pipeline.py` to include session context in the error log messages for each worker:

1. **STT Worker (line 341)** - Change:
   ```python
   # Current:
   logger.error(f"STT Error: {e}")
   
   # Replace with:
   logger.error(f"STT Error: {e}", extra={"session_id": session_id, "audio_length": len(audio_data) if audio_data is not None else 0})
   ```
   Or simpler inline format:
   ```python
   logger.error(f"STT Error [session={session_id}]: {e}")
   ```

2. **LLM Worker (line 384)** - Change:
   ```python
   # Current:
   logger.error(f"LLM Error: {e}")
   
   # Replace with:
   logger.error(f"LLM Error [session={session_id}, {source_lang}->{target_lang}]: {e}")
   ```

3. **TTS Worker (line 414)** - Change:
   ```python
   # Current:
   logger.error(f"TTS Error: {e}")
   
   # Replace with:
   logger.error(f"TTS Error [session={session_id}, voice={voice}]: {e}")
   ```

4. **Player Worker (line 439)** - The player worker doesn't have session_id directly accessible in the same scope. Add context if self.session is available:
   ```python
   # Current:
   logger.error(f"Player Error: {e}")
   
   # Replace with:
   session_id = self.session.session_id if self.session else "unknown"
   logger.error(f"Player Error [session={session_id}]: {e}")
   ```

**Use inline format** (simpler than extra dict) since loguru handles structured logging well with f-strings.
  </action>
