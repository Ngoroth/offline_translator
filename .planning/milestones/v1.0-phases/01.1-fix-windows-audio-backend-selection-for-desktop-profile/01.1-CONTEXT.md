# Phase 01.1: Fix Windows audio backend selection for desktop profile - Context

**Gathered:** 2026-02-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix runtime audio recorder backend selection so the `desktop_rtx4070` profile (platform `windows`) does not attempt Linux-only `arecord` capture. This phase is limited to selecting the correct input backend for desktop profile startup while preserving existing Raspberry Pi audio behavior.

</domain>

<decisions>
## Implementation Decisions

### Backend selection behavior
- Recorder backend must be selected from profile/runtime context, not hardcoded globally.
- Windows desktop profile must use a Windows-compatible capture path (sounddevice/PortAudio), not `arecord` subprocess.
- Raspberry Pi deployment profile must continue using ALSA/`arecord` behavior already in use.

### Selection source of truth
- Selection should key off active app settings/profile intent (for example `settings.platform`) so `--profile` launches behave deterministically.
- Do not rely only on host OS auto-detection when profile explicitly states target platform.

### Audio device compatibility
- Existing input/output device resolution flow in `main.py` remains the integration point for selecting device ids/names.
- Linux ALSA string devices configured for Pi must remain valid in the Pi path.
- Windows path should accept resolved numeric device indices used by sounddevice.

### Error handling UX
- If recorder backend startup fails, errors should remain actionable and indicate backend-relevant guidance.
- Desktop profile launch should not fail with "arecord command not found" when correct Windows backend is available.

### Test expectations
- Add/adjust tests to cover backend choice for desktop vs Pi profiles.
- Preserve existing recorder error-path coverage where it still applies to Pi/ALSA backend behavior.

### Claude's Discretion
- Exact module shape for backend selection (factory, strategy, or conditional wiring).
- Whether shared recorder interface lives in `app.core.audio` package exports or a new backend module.
- Minor wording of backend-specific startup log messages.

</decisions>

<specifics>
## Specific Ideas

- Keep player path unchanged unless backend split requires minimal interface alignment.
- Favor a small, explicit backend selector over broad audio refactors in this urgent phase.

</specifics>

<deferred>
## Deferred Ideas

- Removing duplicate legacy `src/app/core/audio.py` implementation (separate cleanup).
- Larger cross-platform audio architecture redesign beyond desktop-profile backend correction.
- Non-desktop profile enhancements unrelated to Windows recorder startup.

</deferred>
