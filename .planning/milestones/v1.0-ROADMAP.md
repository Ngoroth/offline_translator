## Overview

## Milestone Summary

**Decimal Phases:**
- Phase 01.1 inserted after Phase 1 for urgent Windows recorder backend fix
- Phase 01.2 inserted after Phase 1 for urgent VAD playback timing behavior fix

**Key Decisions:**
- Profile selection remains explicit via `--profile`; no auto-detection magic
- Recorder backend selection uses `settings.platform` intent, with host fallback only for `auto`
- Playback policy override is runtime-only (`--playback-during-recording`) and does not mutate `config.yaml`
- Deploy path standardized to preflight -> rsync -> remote `uv sync`

**Issues Resolved:**
- Windows desktop launches no longer hit Linux-only `arecord` dependency on desktop profile
- Pre-release playback timing now matches speaker/headset policy controls
- Deploy workflow moved from manual steps to one command with actionable failure output

**Issues Deferred:**
- Human hardware confirmation remains for some playback behavior checks
- Live-host dependency keeps `DEPLOY-01` partially environment-bound during audit

**Technical Debt Incurred:**
- Deploy host/path constants remain hardcoded pending configurability follow-up
- No automatic post-deploy runtime smoke check on target hardware
