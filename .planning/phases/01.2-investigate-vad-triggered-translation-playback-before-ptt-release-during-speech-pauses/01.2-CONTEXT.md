**Status:** Ready for planning

<domain>
## Phase Boundary

Clarify and control when translated playback can start before PTT release during speech pauses, using existing behavior as baseline and keeping this capability opt-in.

</domain>

<decisions>
## Implementation Decisions

### Early playback gate
- Keep early playback capability available, but make sure it is explicitly gated by a user-facing mode/flag.
- Default must be OFF for all profiles.
- Reuse the existing mode/setting already present in the system (user referenced existing headphone-oriented mode), rather than introducing a net-new feature concept.

### Configuration surface
- Mode is configurable via both config and CLI override.
- CLI override is runtime-only (applies to current launch) and must not persist back to `config.yaml`.

### Pause timing behavior
- Existing pause-delay behavior/setting already in system is kept as-is for this phase.
- Do not change current default pause-delay values in this phase.

### Resume-speech behavior while holding PTT
- Do not introduce a new policy (no new forced stop/duck rule in this phase).
- Keep current runtime behavior as-is when speech resumes during early playback.

### Claude's Discretion
- Exact naming/help text alignment for the existing flag/mode in CLI and config.
- How prominently to document current overlap behavior in user-facing docs.
- Queueing strategy details for multiple chunks before release, unless existing behavior is already clear and should be preserved unchanged.

</decisions>

## Specific Ideas

- User remembers this behavior already exists and wants it hidden behind a flag and disabled by default right now.
- User prefers minimal behavioral change for this urgent phase and to preserve current runtime semantics where possible.
